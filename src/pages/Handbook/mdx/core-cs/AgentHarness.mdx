## 한 턴이 처리되는 순서

Agent가 "한 단계"를 진행할 때 Harness 안에서는 아래 순서가 반복된다. 이 반복 자체는 <DocLink slug="agent-loop">Agent Loop</DocLink>에서 자세히 다룬다.

<MermaidDiagram
  code={`flowchart TB
  A["1. 컨텍스트 조립"] --> B["2. 모델 호출"]
  B --> C{"3. 출력 검증"}
  C -->|"형식 오류"| R["오류 내용을 붙여 재요청"]
  R --> B
  C -->|"도구 호출"| D["4. 권한 확인 후 도구 실행"]
  D --> E["5. 결과 정리 · 상태 저장"]
  E --> F{"6. 종료 조건?"}
  F -->|"계속"| A
  C -->|"최종 답변"| G["응답 반환"]
  F -->|"제한 도달"| G`}
/>

<KeyTable
  columns={["단계", "Harness가 결정하는 것"]}
  rows={[
    ["1. 컨텍스트 조립", "이번 호출에 무엇을 넣고 무엇을 뺄지. 자세한 기준은 Context Engineering 문서에서 다룬다."],
    ["2. 모델 호출", "어떤 모델을 쓸지, timeout과 재시도 횟수를 얼마로 둘지."],
    ["3. 출력 검증", "스키마가 맞는지, 정책상 허용되는 행동인지. 틀리면 오류 메시지를 다시 넣어 모델이 고치게 한다."],
    ["4. 도구 실행", "이 사용자·이 단계에서 이 도구를 써도 되는지, 사람 승인이 필요한지."],
    ["5. 결과 정리", "도구 원본 결과를 그대로 넣을지, 요약·잘라내기 후 넣을지."],
    ["6. 종료 판단", "목표를 달성했는지, 단계·시간·비용 제한에 걸렸는지."],
  ]}
/>

각 단계는 이 섹션의 문서에서 자세히 다룬다. 도구 정의와 실행은 <DocLink slug="agent-tool-use">Tool Use</DocLink>, 사람 승인은 <DocLink slug="agent-hitl">Human-in-the-Loop</DocLink>, 권한과 격리는 <DocLink slug="agent-guardrails-authz">Guardrails / Identity / Authorization</DocLink>, 재시도와 checkpoint는 <DocLink slug="agent-reliability">Reliability</DocLink>에 있다.

<Callout variant="info" title="모델은 부품, Harness는 제품">
  <p>같은 작업을 다른 모델로 바꿔도 Harness의 검증·제한·상태 저장은 그대로 동작해야 한다. 안전과 신뢰성을 프롬프트("절대 삭제하지 마")에만 맡기지 말고, 도구 권한과 검증 코드로 강제하는 것이 원칙이다.</p>
</Callout>
