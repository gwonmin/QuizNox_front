## 넘겨줄 때의 계약

Agent 사이에서 일을 넘길 때는 대화 원문 전체가 아니라 받는 쪽에 필요한 최소 정보를 정해진 형식으로 넘긴다. AWS [Well-Architected Agentic AI Lens](https://docs.aws.amazon.com/wellarchitected/latest/agentic-ai-lens/agentops01-bp02.html)(2026.10 확인)도 handoff를 "작업 설명 · 완료한 일 · 기억 · 넘기는 이유"를 담은 버전 있는 스키마로 정의하라고 권한다.

## 그래프로 표현하기

여러 단계와 분기 · 루프를 코드로 통제하려면 작업을 그래프(노드 + 엣지 + 공유 상태)로 표현한다. LangGraph 같은 프레임워크가 이 방식을 쓴다.

<MermaidDiagram
  code={`flowchart TB
  START(["시작"]) --> AGENT["agent 노드: 모델이 판단"]
  AGENT -->|"도구 필요"| TOOLS["tools 노드: 도구 실행"]
  TOOLS -->|"결과 반환"| AGENT
  AGENT -->|"승인 필요"| HUMAN["human 노드: 사람 승인"]
  HUMAN -->|"승인 완료"| AGENT
  AGENT -->|"답변 완료"| END_NODE(["완료"])`}
/>

<KeyTable
  columns={["개념", "역할"]}
  rows={[
    ["State (공유 상태)", "그래프 전체가 읽고 쓰는 객체. 노드 사이 정보 전달 통로"],
    ["Node", "작업 단위. 모델 호출, 도구 실행, 조건 판단 등"],
    ["Conditional Edge", "결과에 따라 다음 노드를 고른다. 분기 · 루프를 만드는 핵심"],
    ["병렬 브랜치", "독립 노드를 동시에 실행하고 다음 노드에서 결과를 합친다"],
    ["Checkpoint", "노드 단위로 상태를 저장해 장애 후 재개, 이전 시점으로 되돌리기"],
    ["Interrupt", "특정 노드 앞에서 멈추고 사람 입력을 받은 뒤 이어서 실행"],
  ]}
/>
