## ReAct 패턴 (Reasoning + Acting)

AI Agent의 핵심 실행 패턴으로, **추론(Thought)과 행동(Action)을 번갈아 수행**하며 **관찰(Observation) 결과를 다음 추론에 반영**한다.

  O1["Observation 1\n(결과 확인)"]

## 도구 연결 표준: MCP

**Model Context Protocol(MCP)** 은 호스트(IDE·런타임)가 서버(파일·DB·API 래퍼)에 붙는 규약이다. 에이전트마다 커스텀 REST를 반복하기보다 MCP 서버를 두면 도구 스키마·권한 경계를 맞추기 쉽다. 다만 MCP는 인증·승인·레이트 리밋을 대신하지 않는다. 도구 정의와 MCP 구조는 <DocLink slug="agent-tool-use">Tool Use</DocLink>에서 자세히 다룬다.

## LangChain / LangGraph 심화

LangChain은 **부품(모듈)**, LangGraph는 그 부품을 **조립하는 설계도(그래프)**이다. 이 관계를 단계적으로 풀어본다.

### 1단계: 부품 이해 — LangChain 핵심 모듈

LangChain은 LLM 애플리케이션에 필요한 모듈을 제공하고, 이들을 파이프(`|`) 연산자로 연결한다.

### 2단계: 조립 — LangGraph

단순 체인(`A → B → C`)은 직선형이라 "도구를 쓸지 말지 LLM이 판단"하는 루프를 표현할 수 없다. LangGraph는 노드 · 조건부 엣지 · 공유 상태로 이루어진 그래프로 이 루프와 분기를 표현한다. 그래프의 구성 요소(State, Node, Conditional Edge, Checkpoint, Interrupt)와 체인과의 비교는 <DocLink slug="agent-orchestration">Orchestration</DocLink>에서 다룬다.

### 3단계: 실전 — "여행 계획 Agent" 동작 흐름

부품(LangChain 모듈)을 LangGraph 그래프로 조립하면 아래와 같이 동작한다. 사용자가 "이번 주말 부산 여행 계획 세워줘"라고 요청했을 때의 전체 흐름이다.

> 핵심은 **agent ↔ tools 루프**이다. LLM이 매 회차마다 "어떤 도구를 호출할지" 또는 "답변을 완료할지"를 **자율적으로 판단**한다. 3회차에서 Retriever Tool을 호출한 것이 RAG가 Agent 안에서 **도구 중 하나로 작동**하는 대표적인 패턴이다. 이 루프 구조가 LangGraph가 아닌 단순 체인으로는 불가능한 이유이다.
