## 무엇을 평가하나

  columns={["대상", "질문", "예시 지표"]}

    ["경로 (trajectory)", "합리적인 순서로 목표에 도달했나", "기대 단계 포함 비율, 불필요한 단계 수"],
    ["도구 선택", "필요한 도구를 골랐고 불필요한 도구는 안 썼나", "올바른 도구 호출 비율"],
    ["도구 인자", "인자가 정확했나", "스키마 위반률, 인자 정확도"],
    ["검색", "필요한 근거를 찾아왔나", "Context Precision · Recall (RAG 문서 참고)"],
    ["지연 · 비용", "허용 범위 안인가", "p95 지연, 작업당 토큰 · 비용, 단계 수"],
    ["안전", "하면 안 되는 일을 했나", "권한 밖 시도, 승인 없는 고위험 행동, 민감정보 노출"],

최종 답이 맞아도 경로가 나쁠 수 있다. 예를 들어 같은 조회를 다섯 번 반복했거나, 승인이 필요한 행동을 건너뛰었다면 운이 좋았던 것이다. 검색 품질 지표는 <DocLink slug="rag">RAG</DocLink> 문서의 평가 지표와 같다.

## 평가 단위

<MermaidDiagram
  code={`flowchart TB
  subgraph thread ["Thread: 대화 전체"]
    direction TB
    subgraph trace1 ["Trace: 요청 1의 전체 실행"]
      direction LR
      R1["Run: 모델 호출"] ~~~ R2["Run: 도구 호출"] ~~~ R3["Run: 모델 호출"]
    end
    subgraph trace2 ["Trace: 요청 2의 전체 실행"]
      direction LR
      R4["Run: 모델 호출"] ~~~ R5["Run: 도구 호출"]
    end
    trace1 ~~~ trace2
  end`}
/>

<KeyTable
  columns={["단위", "평가 질문", "예"]}
  rows={[
    ["Run (단계)", "이 한 번의 호출이 맞았나", "의도 분류가 맞았나, 도구 인자가 맞았나"],
    ["Trace (요청)", "요청 하나를 잘 처리했나", "경로 · 최종 답 · 지연 · 비용"],
    ["Thread (대화)", "대화 전체로 목표를 이뤘나", "사용자 의도 파악, 최종 해결 여부, 같은 질문 반복 여부"],
  ]}
/>

LangSmith 문서는 이 세 단위의 평가를 구분해 지원하고, thread 단위 평가는 대화가 끝난 뒤 한 번 실행해 의도 · 결과 · 경로를 매기는 방식으로 설명한다([multi-turn evaluators](https://docs.langchain.com/langsmith/online-evaluations-multi-turn), 2026.10 확인).

Trajectory 비교의 네 가지 기준(strict, unordered, subset, superset)은 LangChain의 [agentevals](https://docs.langchain.com/langsmith/trajectory-evals)에서 쓰는 분류다.
