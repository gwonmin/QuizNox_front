## Function calling의 흐름

<MermaidDiagram
  code={`flowchart TB
  A["1. Harness: 도구 목록과 스키마를 컨텍스트에 넣음"] --> B["2. Model: 도구 호출 출력 (이름 + JSON 인자)"]
  B --> C{"3. Harness: 스키마 · 권한 검증"}
  C -->|"실패"| E["오류 메시지를 결과로 돌려줌"]
  C -->|"통과"| D["4. Harness: 도구 실행 (timeout · 격리)"]
  D --> F["5. 결과 정리 후 컨텍스트에 추가"]
  E --> G["6. Model: 결과를 보고 다음 행동 결정"]
  F --> G`}
/>

모델이 출력하는 것은 "실행 요청"일 뿐이다. 실행 여부, 실행 방식, 결과를 얼마나 보여줄지는 모두 <DocLink slug="agent-harness">Agent Harness</DocLink>가 결정한다.

## 도구 정의의 구성

```json
{
  "name": "get_order",
  "description": "주문 번호로 주문 상태를 조회한다. 환불 가능 여부 판단 전에 먼저 호출한다.",
  "input_schema": {
    "type": "object",
    "properties": {
      "order_id": { "type": "string", "pattern": "^ORD-[0-9]{8}$" },
      "fields": {
        "type": "array",
        "items": { "enum": ["status", "amount", "paid_at", "items"] }
      }
    },
    "required": ["order_id"]
  }
}
```

## MCP (Model Context Protocol)

MCP는 Agent 앱(호스트)과 도구 제공자(서버) 사이의 표준 프로토콜이다. 2024.11에 Anthropic이 공개했고, 이후 여러 Agent 제품과 프레임워크가 지원한다. 명세는 [modelcontextprotocol.io](https://modelcontextprotocol.io)에 있다.

<MermaidDiagram
  code={`flowchart LR
  subgraph host [Agent 앱 = MCP 호스트]
    direction TB
    M["Model"] <--> CL["MCP 클라이언트"]
  end
  subgraph servers [MCP 서버]
    direction TB
    S1["코드 저장소 서버"] ~~~ S2["DB 서버"] ~~~ S3["파일시스템 서버"]
  end
  CL <-->|"표준 프로토콜"| servers`}
/>

  columns={["구분", "앱에 직접 구현한 도구", "MCP 서버"]}
  rows={[
    ["재사용", "그 앱에서만 쓸 수 있다", "MCP를 지원하는 여러 앱에서 같은 서버를 쓴다"],
    ["제공하는 것", "도구(함수)", "도구 + 리소스(읽을 데이터) + 프롬프트 템플릿"],
    ["적합한 경우", "앱 고유의 비즈니스 로직, 강한 통제가 필요한 쓰기 작업", "사내 시스템 · 외부 서비스를 여러 Agent에 공통으로 연결할 때"],
    ["주의", "앱마다 중복 구현", "서버도 실행 코드다. 출처를 확인하고, 권한을 좁히고, 도구 설명에 숨은 지시(prompt injection)를 경계한다"],
  ]}

<Callout variant="warning" title="실패를 숨기지 않기">
  <p>도구가 실패했는데 빈 결과나 "완료"를 돌려주면, 모델은 성공한 줄 알고 그럴듯한 답을 지어낸다. 실패는 실패라고, 이유와 함께 돌려준다.</p>
</Callout>
