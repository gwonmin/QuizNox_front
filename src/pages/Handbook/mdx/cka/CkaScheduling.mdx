## 예시

```bash
kubectl label node worker1 disk=ssd
```

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: batch
  namespace: shop
spec:
  nodeSelector:
    disk: ssd
  tolerations:
  - key: dedicated
    operator: Equal
    value: batch
    effect: NoSchedule
  containers:
  - name: app
    image: nginx
    resources:
      requests:
        cpu: 100m
        memory: 128Mi
      limits:
        cpu: 200m
        memory: 256Mi
```

nodeSelector 대신 필수 affinity를 쓸 때다. 라벨이 없으면 이 Pod도 Pending이다.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: batch-affinity
  namespace: shop
spec:
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
        - matchExpressions:
          - key: disk
            operator: In
            values:
            - ssd
  containers:
  - name: app
    image: nginx
```

LimitRange의 default는 컨테이너가 limits를 생략했을 때만 채운다. ResourceQuota는 네임스페이스의 requests 합을 넘기면 새 Pod를 거절한다.

```yaml
apiVersion: v1
kind: LimitRange
metadata:
  name: shop-limits
  namespace: shop
spec:
  limits:
  - type: Container
    defaultRequest:
      cpu: 100m
      memory: 128Mi
    default:
      cpu: 200m
      memory: 256Mi
---
apiVersion: v1
kind: ResourceQuota
metadata:
  name: shop-quota
  namespace: shop
spec:
  hard:
    pods: "10"
    requests.cpu: "2"
    requests.memory: 2Gi
```

kubectl get pod batch -n shop -o wide
